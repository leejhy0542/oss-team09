# 모아씀

셰어하우스나 룸메이트가 공동 지출을 정산하고 공용 냉장고 재고를 관리하는 웹 앱입니다.


## 사용 방법

1. 함께 사는 사람의 이름을 입력합니다. 2~4명까지 설정할 수 있습니다.
2. 공동 비용 계산에 지출 이름, 결제 금액, 결제자와 나눌 사람을 입력하고 **정산에 추가하기**를 누릅니다. 금액 입력 아래의 빠른 입력 버튼을 사용하거나 카테고리를 직접 추가할 수 있습니다. 추가한 카테고리는 저장되어 월별 합계에 반영됩니다. 지출만 정산에 등록됩니다.
3. 장보기 기록에 산 식품과 유통기한을 추가하고 **장보기 기록하기**를 누릅니다. 식품만 공용 냉장고에 등록됩니다.
4. 냉장고 목록에서 품목명 옆의 냉장·실온 보관 표시와 유통기한 임박 여부를 확인하고, 식품을 다 먹었거나 버렸을 때 상태를 표시합니다.
5. 식품을 다음 장보기 목록에 담거나 품목을 직접 추가합니다. 이후 장보기 기록에 등록하면 같은 이름의 목록 항목은 자동으로 제거됩니다.
6. 현재 정산의 송금 건마다 실제 송금을 마친 뒤 해당 건의 **송금 완료**를 누릅니다. 완료한 송금은 잔액에서 차감되고 완료 내역에 따로 남으며, 나머지 송금은 대기 상태로 유지됩니다.
7. 공용 냉장고의 **메뉴 추천받기**를 누르면 보관 중인 임박 식품을 활용한 메뉴를 추천받습니다. 추천 중에는 버튼이 비활성화되고, 요청이 끝나면 다시 사용할 수 있습니다.


## LLM 연동 범위

공용 냉장고의 메뉴 추천은 서버에서 Google Gemini API를 호출해 동작합니다. 서버가 저장된 냉장고 식품 중 임박 식품을 코드로 선별하고, 재료 이름만 LLM에 전달합니다. LLM은 해당 재료를 활용한 메뉴와 간단한 조리 방법을 한 줄로 생성하며, 결과는 화면에 표시됩니다.

API 키와 모델은 서버 운영자가 환경변수로 설정합니다. 일반 사용자는 키를 입력할 필요가 없습니다. 임박 식품이 없으면 외부 API를 호출하지 않습니다. 호출 한도 초과, 통신 오류, 응답 오류 또는 기본 10초의 제한 시간 초과 시 자동 재시도 없이 실패 안내를 표시하며, 기존 정산·냉장고 기능은 계속 사용할 수 있습니다.

## 계산과 재고 규칙

부담액·최소 송금·화면의 기한 표시 계산은 [`Calcul.js`](./Calcul.js)에, 서버의 잔액·재고 규칙은 [`server/rules.js`](./server/rules.js)에 있습니다. 메뉴 추천 재료 선별은 [`server/menu/menu-rules.js`](./server/menu/menu-rules.js)에, 사람별 냉장고 점유는 [`server/fridge-stats.js`](./server/fridge-stats.js)에 분리해 화면과 외부 API 없이 테스트할 수 있습니다.

- **1인당 부담액**: 금액을 부담 인원수로 나눈 몫을 각 사람에게 배정합니다. 나머지 원은 결제한 사람이 추가로 부담합니다.
- **최소 송금 정산**: 지출별 결제액과 개인 부담액을 누적해 잔액을 계산하고, 송금 횟수가 가장 적은 조합을 표시합니다.
- **송금별 정산 완료**: 각 송금을 개별 완료 처리합니다. 완료한 송금액을 잔액에서 반영한 뒤 남은 금액만 다시 정산하며, 완료 송금 내역과 완료일을 따로 표시합니다. 새 지출이 등록되면 기존 완료 송금을 반영해 미정산 잔액을 계산합니다.
- **보관 방법 표시**: 식품을 직접 등록할 때 냉장 보관 또는 실온 보관을 선택할 수 있고, 냉장고 목록에서 이름 옆에 표시합니다. 기존 저장 품목은 냉장 보관으로 표시합니다.
- **유통기한 표시**: 오늘부터 2일 이내면 임박, 지난 경우 폐기 확인 대상으로 표시합니다. 식품 등록 시 유통기한은 선택 입력입니다.
- **메뉴 추천 재료**: 한국 시간 기준 오늘부터 2일 이내에 기한이 도래하고 상태가 보관 중인 식품만 선택합니다. 기한 경과·미입력·다 먹음·폐기 식품은 제외합니다. 선별 함수는 식품 목록, 기준 날짜, 임박 기준 일수(기본 2일)를 받으며 원본 목록은 변경하지 않습니다.
- **재고 상태**: 냉장고 식품을 보관 중, 다 먹음, 폐기로 구분합니다. 다 먹음·폐기 상태는 취소해 다시 보관 중으로 되돌릴 수 있으며, 상태 변경 후 일주일이 지나면 공용 냉장고에서 자동 삭제됩니다. 지출 내역을 지워도 냉장고 재고는 별도로 유지됩니다.
- **사람별 냉장고 점유**: 식품마다 주인을 저장하고, 사람별로 등록한 식품 수와 보관 중·다 먹음·폐기 수, 폐기율을 계산합니다. 폐기율은 다 먹음과 폐기를 합친 수 중 폐기 비율이며, 보관 중인 식품은 빼고 계산합니다. 주인의 기본값은 결제한 사람이고 등록할 때나 등록한 뒤에 바꿀 수 있으며, 주인을 고르지 않았거나 멤버가 아니면 다 같이 먹는 공용 식품으로 모아 셉니다. 일주일이 지나 냉장고 목록에서 사라진 식품도 기록에는 포함합니다.
- **다음 장보기**: 식품을 목록에 담을 수 있습니다. 같은 이름의 식품을 새 장보기 기록에 등록하면 목록에서 제거됩니다.
- 금액은 1원 이상의 정수로 입력합니다. 잘못된 입력이나 서버 요청 오류는 화면에 안내합니다.

예를 들어 10,000원을 3명이 나누면 기본 부담액은 1인당 3,333원이며, 나머지 1원은 결제한 사람이 부담합니다.

### 정산 함수 예시

```js
import {
  calculateMinimumTransfers,
  calculateShares,
} from "./Calcul.js";

const shares = calculateShares(10000, ["민지", "서준", "하은"], "민지");
// [{ name: "민지", amount: 3334 }, { name: "서준", amount: 3333 }, { name: "하은", amount: 3333 }]

const transfers = calculateMinimumTransfers({
  민지: 6666,
  서준: -3333,
  하은: -3333,
});
// [{ from: "서준", to: "민지", amount: 3333 },
//  { from: "하은", to: "민지", amount: 3333 }]
```

## 파일

- `index.html`: 장보기·식품 입력, 정산, 냉장고 및 다음 장보기 화면
- `style.css`: 반응형 화면 스타일
- `script.js`: 장보기·재고·목록·정산 화면 동작 및 [`api.js`](./api.js)를 통한 서버 연동
- `api.js`: 서버 API 요청 함수
- `Calcul.js`: 유통기한 임박 기간 판정, 부담액·최소 송금·월별 사용자 카테고리 합계 계산
- `menu-suggestion.js`: 메뉴 추천 버튼, 로딩 상태, 결과와 오류 안내 표시
- `server/menu/menu-rules.js`: 메뉴 추천에 사용할 임박 식품 선별
- `server/fridge-stats.js`: 사람별 냉장고 점유와 폐기율 계산
- `server/menu/llm-client.js`: Gemini API 호출, 시간 제한과 실패 처리
- `tests/menu-rules.test.js`: 재료 선별 규칙과 입력 검증 테스트
- `tests/fridge-stats.test.js`: 사람별 냉장고 점유와 폐기율 테스트
- `tests/llm-client.test.js`: 가짜 API 응답을 사용하는 LLM 호출 테스트
- `tests/menu-suggestion.test.js`: 가짜 화면 요소와 API를 사용하는 화면 동작 테스트


## 서버 실행

Node.js 20.6 이상이 필요합니다.

```bash
npm install
cp .env.example .env
```

이미 `.env`가 있다면 복사 명령은 생략하고 필요한 환경변수만 추가합니다. 메뉴 추천을 사용하려면 `.env`에 다음 설정을 입력합니다.

```dotenv
GEMINI_API_KEY=발급받은_키
GEMINI_MODEL=gemini-3.5-flash-lite
```

실제 키는 `.env`에만 저장합니다. `.env.example`의 `GEMINI_API_KEY`는 빈 값으로 유지합니다. 선택한 모델의 무료 사용 가능 여부와 한도는 사용하는 프로젝트에서 별도로 확인할 수 있습니다. 키 또는 모델 설정이 없으면 메뉴 추천은 비활성화되며 다른 기능은 사용할 수 있습니다.

```bash
npm start              # http://localhost:3000
```

설정 변경 후에는 서버를 재시작합니다. 화면은 HTML 파일을 직접 여는 대신 위 서버 주소로 접속합니다.

데이터는 `data/state.json`에 저장됩니다. `data/`와 `.env`는 저장소에 올리지 않습니다.

### 테스트와 실제 연결 확인

```bash
npm test               # 계산 규칙, API, LLM 클라이언트와 화면 동작 테스트
```

자동 테스트는 가짜 API 응답(Mock)을 사용하며, 실제 Gemini 호출이나 API 키 없이 실행할 수 있습니다. 재료 선별의 날짜 경계와 상태, 정상 응답, HTTP 429·통신 오류·시간 초과, 요청 중 중복 클릭 방지 등을 확인합니다.

실제 연결은 서버를 실행한 뒤 식품의 이름과 오늘부터 2일 이내의 기한을 입력하고, **추가**와 **장보기 기록하기**를 눌러 저장한 후 **메뉴 추천받기**로 확인합니다. 재료가 있으면 실제 API 한도를 사용하므로 필요한 확인에만 호출합니다. 메뉴 추천은 서버에 저장된 냉장고 식품을 기준으로 동작합니다.

## API

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | /api/state | 첫 화면용 전체 상태 (정산 결과, 유통기한 판정 포함) |
| GET, PUT | /api/members | 멤버 조회, 변경 (2~4명, 지출이 있으면 변경 불가) |
| POST | /api/categories | 공동 지출 카테고리 추가 |
| GET, POST | /api/expenses | 정산 지출 조회, 등록 |
| DELETE | /api/expenses/:id | 지출 하나 삭제 |
| DELETE | /api/expenses | 지출과 송금 기록 전체 삭제 (냉장고는 유지) |
| GET | /api/settlement | 사람별 잔액과 최소 송금 목록 |
| POST | /api/transfers | 송금 완료 처리 (현재 정산 결과에 있는 송금만) |
| GET, POST | /api/fridge | 냉장고 목록(임박순), 식품 등록 (하나 또는 { items: [...] }). 같은 이름은 다음 장보기 목록에서 빠짐 |
| PATCH | /api/fridge/:id | 상태 변경 (available, consumed, discarded). 다 먹음·폐기는 바꾼 시각을 저장하고 7일 뒤 목록에서 빠짐 |
| POST | /api/fridge/menu-suggestion | 서버에 저장된 임박 식품으로 Gemini 메뉴 추천 (요청 본문 없음) |
| GET, POST | /api/shopping-list | 다음 장보기 목록 조회, 추가 |
| DELETE | /api/shopping-list/:id | 목록 항목 삭제 |

에러는 `{ "error": "메시지" }` 형태로 돌려줍니다. LLM이 연결되지 않았거나 호출이 실패하면 메뉴 제안 API는 `suggestion: null`을 돌려주고 나머지 기능은 그대로 동작합니다.

### 메뉴 추천 응답

```json
{
  "items": ["달걀", "토마토"],
  "suggestion": "달걀과 토마토를 볶아 토마토달걀볶음을 만드세요.",
  "reason": "ok"
}
```

`items`는 선별된 재료 이름 배열이며, `suggestion`은 생성된 문장 또는 `null`입니다. 추천 문장은 호출마다 달라질 수 있습니다. 아래 상태는 HTTP 200 응답의 `reason`으로 구분합니다.

| reason | 의미 |
| --- | --- |
| `ok` | 추천 성공 |
| `no-items` | 임박 식품 없음, LLM 호출 생략 |
| `llm-disabled` | LLM 객체가 없거나 키·모델 설정 누락으로 비활성화, 호출 생략 |
| `llm-failed` | LLM 호출 실패 또는 유효한 추천 문장 없음 |

프런트는 `api.js`의 함수를 가져와 서버와 통신하며, 데이터는 서버의 `data/state.json`에 저장됩니다.

```js
import { api } from "./api.js";
const state = await api.getState();
await api.addExpense({ title, amount, payer, participants });
await api.addFridgeItems([{ name, expirationDate }]);
```
